🏗️ 레짐(Market Regime) vs 감독관(Market ENV)
둘 다 "상승장/하락장" 개념을 다루지만 범위가 다르다.
레짐 (Market Regime)
현재 분석 중인 이 종목의차트 데이터로 판별
ADX + BB폭 + MA20 기울기
→ 상승/하락/횡보/전환

종목 단위
감독관 (Market ENV)
지수, VIX, 금리, 달러인덱스, 원자재, 도미넌스 등에서 수집한 거시 시장환경 데이터
→ 시장 위험하면 BUY 제동

시장 전체
분석 흐름:
BT (순수 기술적 필터) → 레짐 (종목 추세 보정) → 감독관 (시장 전체 제동)

감독관이 최상위에서 "시장 자체가 위험" 판단하면,
레짐이 "이 종목 상승추세니까 진입하자" 해도 최종 BUY 차단.
백테스트(BT)에서는:
• BT는 둘 다 적용 안 함 (순수 기술적 필터만)
• 레짐 OFF + 감독관 데이터 없음 = BT와 거의 동일한 결과
• 레짐 OFF + 감독관 데이터 있음 = BT 결과에서 감독관 제동만 추가

워크포워드 테스트 — 과최적화 검증
▼
데이터를 앞부분(학습)과 뒷부분(검증)으로 나눠서,
학습 구간에서 좋았던 파라미터가 미래 데이터에서도 먹히는지 확인.
🎯 판정 기준
✅ 과최적화 아님
검증 구간 수익률 ≥ 0% AND 승률 차이 ≤ 10%p
→ 이 파라미터는 실전 투입 가능
🟡 주의
검증 구간 수익률 ≥ 0% BUT 승률 크게 하락
→ 약간 과최적화 경향. 파라미터 조정 필요
🔴 과최적화 의심
검증 구간 수익률 < 0%
→ 이 파라미터는 실전에서 손실 날 가능성 높음. 사용 금지
📐 학습 비율 설정
70% 기본 권장 (학습 70 : 검증 30)
60% 보수적 (검증 구간 넓게)
80% 공격적 (데이터 적을 때만)

검증 구간이 너무 짧으면(30봉 미만) 의미 없음.
⚠️ 핵심 원칙
학습 구간에서 수익률 50%여도, 검증 구간에서 -10%면
그건 과거에만 통하는 설정이다.
화려한 학습 결과에 속지 말 것. 검증 구간이 진짜 실력.

🏦 헤지펀드 / 퀀트펀드
Renaissance Technologies, Two Sigma, Citadel 같은 세계 최대 펀드는 100% 알고리즘으로 매매한다.

이들의 프로세스:
① 수백 개 기술지표 조합으로 전략 설계
② 백테스트로 과거 데이터 검증
③ 워크포워드로 과최적화 필터링
④ 페이퍼 트레이딩(시뮬레이션)으로 실시간 검증
⑤ 모든 단계 통과한 전략만 실전 투입

수조 원을 운용하는 펀드도 이 과정을 생략하지 않는다.
검증 없이 실전에 넣는 건 도박이라는 걸 알기 때문
📊 증권사 퀀트 리서치팀
국내 주요 증권사(삼성증권, 미래에셋, NH투자 등)에는 퀀트팀이 있다.

이들은 RSI, MACD, 볼린저밴드 같은 기술지표 조합으로 종목을 스크리닝하고, 백테스트로 전략을 검증한 뒤 리서치 리포트에 반영한다.

애널리스트가 "이 종목 매수 추천"이라고 할 때, 그 뒤에는 시스템적 검증이 깔려 있는 경우가 많다.
👨‍💻 전문 개인 트레이더
전업 트레이더들은 TradingView, AmiBroker, QuantConnect 같은 도구로 전략을 코딩하고 백테스트를 실행한다.

파이썬 라이브러리(backtrader, zipline)로 자체 시스템을 만드는 사람도 많고, 유명 트레이더 중 "감으로 매매한다"고 말하는 사람도 실제로는 자기만의 규칙과 검증 프로세스가 있다.

차이는 도구의 이름이 아니라, "신호를 만들고 → 테스트하고 → 검증한 뒤 → 실전에 넣는다"는 이 흐름을 따르느냐 마느냐다.
🎯 핵심 메시지
기관이든 개인이든, 수익을 내는 트레이더의 공통점은 하나다:

"감이 아닌 데이터로 판단하고,
실전 전에 반드시 검증한다."

백테스트는 과거를 본다.
교차검증은 범용성을 본다.
워크포워드는 미래 적합성을 본다.
페이퍼 트레이딩은 실제 시장에서 확인한다.

이 4단계를 거치는 것 자체가, 감으로 매매하는 90%의 투자자보다 앞서는 방법이다.
